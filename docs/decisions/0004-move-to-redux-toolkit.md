# 0004. Move the Redux code to Redux Toolkit

- Date: 2023-08-06
- Status: Accepted

## Context

The Redux code of [0002](0002-manage-state-with-redux.md) was written by hand: action types, action creators, two reducers combined into a root reducer, and container components wrapping each presentational component with `connect`. The dependencies dated from 2018: React 16.3, React Redux 5 and `react-scripts` 1.1.4.

## Decision

`8cb228d` added `@reduxjs/toolkit` 1.9 and upgraded React to 18.2, React Redux to 8.1 and `react-scripts` to 5.0.1. The store is created with `configureStore`, and each feature is a slice made with `createSlice` (`src/features/keyPad/keyPadSlice.js`, `src/features/screen/screenSlice.js`). The components read the store with the `useSelector` and `useDispatch` hooks, and the container components were removed. The same day, `703d90c` renamed the components and variables in English and removed `yarn.lock`, which had sat next to `package-lock.json` since 2018, and `59102ea` moved the images to `public/`.

## Alternatives considered

The commits record no other option. Keeping plain Redux and upgrading only React Redux would have kept the hand-written actions and reducers.

## Consequences

- The action types and action creators are generated by the slices, and each reducer lives in the slice of its feature.
- Measured on 2026-10-20, from the last commit of each era, with the method of [the baseline](../evolution.md#current-baseline): the gzipped JavaScript went from 50,222 B to 60,650 B, and `npm audit` went from 304 to 102 vulnerable packages, a drop that came with the upgrade of `react-scripts` and its dependency tree.
- The project still had no test.
